SO SANH 2 PHUONG AN FIX FINDING #3 - OPEN REDIRECT TRONG OIDC LOGIN

File lien quan: openmetadata-service/src/main/java/org/openmetadata/service/security/AuthenticationCodeFlowHandler.java
Ham lien quan: handleLogin() (dong 364-442), checkAndStoreRedirectUriInSession() (dong 457-464),

BOI CANH - MUC DO NGHIEM TRONG THUC TE
----------------------------------------
Da trace sau hon bao cao goc: day khong chi la "open redirect dan den phishing" ma la
EXFILTRATE TRUC TIEP id_token that. Tai dong 876-884, server tu xay dung URL:

    String url = String.format(
        "%s?id_token=%s&email=%s&name=%s",
        redirectUri,  // <-- gia tri nay khong duoc validate, lay tu request cua attacker
        URLEncoder.encode(credentials.getIdToken().getParsedString(), ...),
        ...
    );
    response.sendRedirect(url);

=> Server tu redirect (302) kem theo id_token that cua nan nhan sang URL do attacker
   chi dinh. Day la exfiltration truc tiep, khong phai chi la "co the bi phishing".

Muc dich cua fix: dam bao redirectUri chi co the tro ve dung origin/callback ma he thong
da cau hinh truoc, khong cho phep attacker tu do chi dinh bat ky domain nao.

DA KIEM TRA: hien tai KHONG CO co che allowlist/trusted-redirect-uri nao san co trong
codebase (grep toan bo openmetadata-service/ va conf/ khong ra ket qua). Nghia la ca 2
phuong an duoi day deu la code MOI, khong phai bat cong tac co san.


PHUONG AN 1: SAME-ORIGIN CHECK (so sanh voi serverUrl da cau hinh)
====================================================================

Cach lam:
  - Class AuthenticationCodeFlowHandler da co san bien `serverUrl` (dung o dong 382 de
    tinh expectedMcpCallback = serverUrl + "/mcp/callback").
  - Them buoc kiem tra: parse origin (scheme + host + port) cua serverUrl va cua
    requestedRedirectUri, so sanh bang nhau. Neu requestedRedirectUri la relative path
    (khong co scheme/host) thi mac dinh an toan (se duoc browser resolve theo origin
    hien tai). Neu la absolute URL nhung khac origin voi serverUrl -> tu choi
    (throw TechnicalException), fallback ve ssoCallbackUrl.

Uu diem:
  1. KHONG can them config moi - dung ngay bien serverUrl da co, khong dong cham den
     conf/openmetadata.yaml, khong can migration hay tai lieu huong dan van hanh moi.
  2. It rui ro implement sai - chi la 1 phep so sanh string/URI.getHost(), de review,
     de unit test (chi can vai testcase: same-host OK, khac-host FAIL, relative-path OK).
  3. Nhat quan voi logic da co san trong chinh file nay (dong 383, so sanh
     expectedMcpCallback) - cung 1 tu duy "so voi 1 gia tri server tu biet", khong phai
     pattern moi doi voi codebase.
  4. Dong kin hoan toan ke ho hien tai NEU gia dinh dung: OpenMetadata sau khi login
     chi bao gio redirect ve chinh frontend cua no (cung origin voi server).

Nhuoc diem / Rui ro:
  1. GIA DINH CHUA DUOC XAC NHAN: neu co flow nao hop le can redirect ve 1 origin KHAC
     serverUrl sau khi login (vi du: 1 SPA rieng deploy o domain khac, tich hop iframe,
     hoac 1 flow embedded/plugin), thi same-origin check se lam GAY flow do. Da search
     code hien tai (nhanh 1.13.3) khong thay bang chung ro rang co flow nhu vay, nhung
     KHONG THE loai tru 100% tu code - can hoi truc tiep team frontend/deployment.
  2. serverUrl co the khac voi domain nguoi dung thuc su truy cap (vi du sau reverse
     proxy/load balancer/multiple domain alias) - neu serverUrl config sai lech thuc te,
     co the vo tinh chan ca cac request hop le. Can kiem tra ky gia tri serverUrl duoc
     set the nao trong moi truong UAT/Prod truoc khi deploy fix nay.
  3. Khong linh hoat cho tuong lai neu OpenMetadata can ho tro nhieu frontend origin
     hop phap cung luc (multi-tenant voi domain rieng cho tung tenant, chang han).

  3. Kiem soat ro rang, tuong minh: nguoi van hanh THAY RO trong config dau la nhung

Nhuoc diem / Rui ro:
